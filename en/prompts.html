WoowTech Prompt Library

Have AI build an n8n workflow from one request

44 copy-ready prompts for AI agents such as Claude, Cursor, and Windsurf. Labels for czlonkowski/n8n-mcp v2.79.0 are checked against n8n v2.32.7. The Public API supports POST /api/v1/workflows, uses PUT /api/v1/workflows/:id for updates, and supports POST /api/v1/workflows/:id/activate. Tests are MCP- or trigger-specific, not an undocumented REST operation. Select “Copy” on any card and paste it into your AI conversation.

What this is

Dragging n8n nodes is quick, but engineers and PMs who already write code with AI can work faster: let AI produce workflow JSON and put it into n8n. This handbook contains 44 prompts for real work scenarios. REST labels name only endpoints documented for n8n v2.32.7; MCP-only behavior is named explicitly and may require the selected server’s additional configuration.

There are two integration methods:

  • n8n MCP server (recommended): these cards pin n8n-mcp, not n8n-workflow-builder, at v2.79.0. Do not treat generic names such as create_workflow or activate_workflow as portable: the operation labels below use the pinned server’s actual names. Inspect a diff before allowing a write.
  • Call the REST API directly: generate a curl or SDK call, authenticate with the X-N8N-API-KEY header, and use the documented /api/v1/workflows route printed on the card. On n8n v2.32.7, workflow updates replace the submitted definition with PUT, not PATCH.
Concept: Prompts are not magic. Their value is showing which details to provide: the goal, trigger, input and output formats, and error-handling strategy. Tool names and capabilities differ between MCP servers, so do not substitute another server without checking its documentation.

How to use these prompts (3-minute setup)

  1. Install an n8n MCP server (recommended)

    Add npx -y n8n-mcp@2.79.0 (czlonkowski/n8n-mcp, pinned here). Do not substitute npx @makafeli/n8n-workflow-builder (a different server) without rechecking every operation. Older generic labels such as create_workflow and activate_workflow are not the pinned tool names printed below.

  2. Set the n8n API environment variables

    This MCP version needs N8N_API_URL (for example, https://n8n.woowtech.io) and N8N_API_KEY (create it under Settings → n8n API). Confirm that the target instance is v2.32.7 before relying on the route labels below.

  3. Choose a prompt and select “Copy”

    Paste it into Claude or Cursor. Replace the placeholder-like fields—Slack channel, Airtable base, and sheet name—with your own.

  4. Have AI report before it acts

    For requests that build workflows, keep the instruction “show me the JSON structure before creating it.” This prevents AI from running unpredictably with real credentials.

Tip: You can work without an MCP server. Paste a prompt into Claude or ChatGPT, ask for n8n workflow JSON, then paste it into n8n manually (in the editor, select the whole canvas with Ctrl+A and paste to replace it). Chapter 5 has the complete JSON import process.

A · Workflow generation (create / update / delete)

The most direct category creates a workflow from one request. AI calls POST /api/v1/workflows to create it and decide whether to activate it.

In n8n, create a workflow named “Order notifications”: Webhook trigger (POST /order-in) → Set extracts order_id/total/email → Google Sheets Append to sheet ID 1abcdef, tab “orders” → Slack sends “New order {{ $json.order_id }}, ${{ $json.total }}” to #sales. Show me the workflow JSON for approval before calling n8n_create_workflow. Respond in English.

→ n8n_create_workflow / POST /api/v1/workflows

Example: reviewing JSON before creation is a basic safety practice.

List all workflows currently in n8n, sorted by updatedAt with the most recently changed first. Output: id, name, active status, last update time, and tags. Respond in English.

→ n8n_list_workflows / GET /api/v1/workflows

Get the complete definition of workflow ID xyz789 from n8n. Compare it with the JSON below in diff format and identify changed fields and added nodes. Respond in English.

→ n8n_get_workflow / GET /api/v1/workflows/:id

In workflow ID abc123, change the Slack channel from #sales to #sales-regional and change nothing else. Retrieve the complete workflow, show me the before/after diff, and wait for approval before replacing it. Respond in English.

→ n8n_update_full_workflow / PUT /api/v1/workflows/:id

Duplicate workflow id abc123 into a new workflow with the suffix -staging. In the copy, change every Slack channel to #staging-alerts and the Google Sheet ID to 1STAGING. Keep it inactive. Respond in English.

→ n8n_get_workflow → n8n_create_workflow

Keep workflow ID abc123 inactive while testing. If it has a Webhook, Form, or Chat trigger, use n8n_test_workflow with its documented trigger method three times; otherwise give me the editor steps to run it manually three times. Then list those executions and report any failed node. Activate only after I approve the results. Respond in English.

→ n8n_test_workflow (MCP/trigger-specific) → n8n_executions; no Public API run route

List all workflows and filter names containing “test” or “staging.” Show me the candidates. After I approve, loop over the approved IDs and deactivate them one at a time; report each result and stop on any failure. I will issue a separate instruction for deletion. Respond in English.

→ GET /api/v1/workflows (paginate) → POST /api/v1/workflows/:id/deactivate (explicit loop)

Safety: deactivate first; do not delete proactively.

B · Trigger setup (webhook / cron / watcher)

A trigger is the entry point to a workflow. These prompts show how to specify different trigger types.

Create a workflow whose Webhook listens for POST /line-webhook, uses response mode responseNode (“Using Respond to Webhook Node” in the UI), enables Raw Body, and does not pretend that built-in Webhook authentication can verify LINE HMAC. Verify LINE’s base64 HMAC-SHA256 over the original raw bytes and compare it with X-Line-Signature using a timing-safe comparison. Ordinary Code nodes cannot read named n8n credentials, so do not reference a credential by a display name such as line-secret. Supply the channel secret only through deployment-approved self-hosted environment-variable access (which is configuration-dependent), or delegate verification to a dedicated service/custom node. Then branch to Respond to Webhook: return 401 and stop on mismatch; only the success branch parses and processes events[0]. Never calculate the HMAC from re-serialized JSON. Respond in English.

→ n8n_create_workflow (Webhook Raw Body + Code + IF + Respond to Webhook)

Create a Schedule Trigger workflow that runs at 8:00 every weekday (Monday–Friday) in your timezone. Skip public holidays by calling sub-workflow holiday-check. Note: replace the timezone and holiday calendar with those for your location. Respond in English.

→ n8n_create_workflow (Schedule + Execute Workflow)

Use Gmail Trigger to poll every 5 minutes for new messages with label invoice. Add an IF downstream that continues only when an attachment is a PDF. Use credential gmail-corp. Respond in English.

→ n8n_create_workflow (Gmail Trigger)

Google Drive Trigger watches folder ID 1FOLDER, with event fileCreated, checking every 10 minutes. When a new file appears, extract its text → save it to Airtable base ID appBASE, table Docs. Respond in English.

→ n8n_create_workflow (Drive Trigger + Airtable)

Create two connected workflows: (A) every 15 minutes, Cron queries Notion database ID DB1 for pages with status=Ready; (B) Execute Workflow calls another workflow to process each page and writes the result back to Notion. Keep them separate to avoid one overly complex workflow. Respond in English.

→ n8n_create_workflow ×2

C · Data transformation (Edit Fields / Code / Split Out / Aggregate)

Data shaping is one of the most frequent tasks in a workflow. These prompts let AI choose between Set and Code.

In existing workflow ID abc123, insert a Set node (Edit Fields) after Webhook. Use n8n expressions based on $json to lowercase $json.body.customer.email, convert $json.body.total to a number, and convert $json.body.created_at to ISO 8601 UTC. Discard other fields. Respond in English.

→ n8n_update_full_workflow / PUT /api/v1/workflows/:id (Edit Fields node)

Insert a Code node (JavaScript). Flatten the previous node’s items, including the nested orders array, to one row per order. Keep the original customer_id in every item, expand each order into a separate item, and map its fields from orders[i]. Respond in English.

→ n8n_update_full_workflow / PUT /api/v1/workflows/:id (Code node)

If the API returns one item containing a records array, use Split Out on records to create one item per record. Route categories A/B/C with Switch, process each route with Loop Over Items in batches of 20 to respect rate limits, then use Aggregate to collect processed IDs for one summary message. Respond in English.

→ n8n_update_full_workflow / PUT /api/v1/workflows/:id

Write a Code node that deduplicates by email. For duplicates in one batch, keep only the item with the latest created_at. Provide JavaScript with detailed comments and a separate Python version. Respond in English.

→ n8n_update_full_workflow / PUT /api/v1/workflows/:id (Code node)

Use Edit Fields after merging three upstream nodes (A, B, and C) into one item. Prefix field names with a_*/b_*/c_* to avoid collisions. Fill missing fields with null instead of dropping them. Configure Merge with Number of Inputs = 3, Mode = Combine, and Combine By = Position. Respond in English.

→ n8n_update_full_workflow / PUT /api/v1/workflows/:id (Edit Fields + Merge)

F · Error handling and monitoring (Error Workflow / Retry / Alerting)

Production workflows do fail. What matters is how you recover.

Create a global Error Workflow: Error Trigger → Set extracts workflow name/failed node/error message/timestamp → Slack sends to #n8n-alerts with details in a code block → if the same workflow fails more than 3 times within 24hr, send another message tagging @on-call. Respond in English.

→ n8n_create_workflow (Error Trigger)

In workflow ID abc123 settings, add errorWorkflow: <error workflow ID from the previous prompt>. List every workflow whose name contains -prod and wait for approval. Then retrieve and update each approved workflow one at a time with the complete required body; report each result and stop on failure. Respond in English.

→ GET /api/v1/workflows (paginate) → PUT /api/v1/workflows/:id (explicit loop)

Implement status-aware retries as workflow nodes, not as native Retry On Fail or continueOnFail: true: initialize attempt=0 → HTTP Request returns the full response without throwing on HTTP status → Switch. For 2xx, continue; for 429/500/502/503/504, increment attempt, fail after 5 total attempts, otherwise Wait for an initial 2 seconds doubled after each failure and loop back; for every other status, fail immediately. Keep the final error response for downstream handling. Respond in English.

→ n8n_update_full_workflow (HTTP Request + Switch + Edit Fields + Wait loop)

Create a “Daily health check” workflow: Schedule Trigger runs every day at 07:00 → retrieve every active workflow with pagination → loop over workflow IDs → retrieve every error execution for each workflow with pagination → filter to the previous 24 hours → aggregate errors as a Slack table → send to #n8n-daily-health. When there are no errors, send “Everything is healthy today.” Respond in English.

→ n8n_create_workflow + GET /api/v1/workflows + GET /api/v1/executions (explicit paginated loops)

Create a workflow: Schedule Trigger runs hourly, retrieves executions from the previous hour with documented execution-list pagination, and calculates the failure rate. If it is >5%, notify me. If it is >20%, identify the workflow with the most failures and ask for approval. Treat deactivate_workflow as a generic label; after approval, use the documented deactivation endpoint printed below and notify me. Respond in English.

→ GET /api/v1/executions (paginated loop) → POST /api/v1/workflows/:id/deactivate after approval

Prompt-writing cheat sheet

Across these 44 prompts, five techniques recur:

Say thisNot thisWhy
State the goal + approximate node order: “Webhook → Set → Sheet → Slack” Only “Build a notification workflow” A goal and node order produce JSON closer to the intended shape, reducing revisions
Specify IDs: sheet ID, Notion database ID, channel, credential name “Use my usual sheet” AI has no memory here. Be specific; ambiguity produces unreliable results
Report before acting: “Show me the JSON before creating it” “Build and activate it immediately” One sentence adds a safeguard to requests involving credentials
Include error handling: retry count, statuses to retry, and failure recipient Describe only the happy path Without an error strategy, AI usually skips it; you discover the omission only in production
Test first: “Use a documented trigger or the editor and let me review the execution before activation” Activate immediately after creation A pre-activation test checks the data path without claiming an undocumented Public API run endpoint

FAQ

Must I copy each prompt word for word?
No. These examples show which details to provide: goal, trigger, data flow, error strategy, and report-before-action. Use your own words and replace the ID, channel, and sheet name.
Can I use these without installing an MCP server?
Yes. Paste a prompt into Claude or ChatGPT, ask it to generate n8n workflow JSON, and import it manually (Ctrl+A selects the whole canvas, then paste). Chapter 5 has the complete process. The limitation is that AI cannot call your instance to validate its work and must infer.
Which MCP server should I use: czlonkowski/n8n-mcp or makafeli/n8n-workflow-builder?
This page’s boundaries pin czlonkowski/n8n-mcp at v2.79.0; makafeli/n8n-workflow-builder may use different names or unsupported internal routes. Verify the installed release before switching. Skill Handbook has a more detailed comparison.
Will AI make uncontrolled changes to production workflows?
It can without safeguards. Always request a JSON/diff preview and confirmation. On Enterprise, create a dedicated API key with only the required scopes and project access. On Community/non-Enterprise, API keys have the creator’s full account capabilities and cannot be made read-only or tag-scoped; use a dedicated least-privileged user/project where available, disable write tools in the MCP server, or do not connect it to production.
Do these prompts use many tokens?
The MCP server may put the complete n8n node list into context (czlonkowski/n8n-mcp supports 2,541 nodes), so the first conversation uses more tokens. Usage stabilizes afterward. Choose a strong reasoning model such as Claude Sonnet or GPT-4o: workflows are code, and better judgment produces more accurate output.
What access does MCP need to call the n8n API?
Under Settings → n8n API, create an API key and send it in the X-N8N-API-KEY header. Enterprise lets the creator select API scopes; Community/non-Enterprise keys have the creator’s full account capabilities. Project access still limits which resources that account can reach. Public routes use /api/v1/*; in n8n v2.32.7, credential listing is additionally restricted to the instance owner or an admin.
