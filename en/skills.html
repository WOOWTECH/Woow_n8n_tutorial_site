WoowTech n8n Skill 手冊

裝一顆節點或給 AI 一顆 skill，n8n 立刻多會十件事

n8n 開箱有 400+ 官方節點，全球社群補了另外 2,100+ 顆 community node、還有幾十顆 MCP server 讓 AI agent 直接寫 workflow。這本手冊挑出「家庭／中小企業 / 內部團隊會真的用到」的 10 顆，加上 6 大熱門集合入口、安裝速查、相容性、安全守則、SKILL.md 規格參考。

調查基準：本冊的 star 數、下載數與維護狀態為 2026-08-20 調查當日的 npm／GitHub 公開數據，會隨時間變動；安裝前建議點進原始 repo 再確認一次。

n8n 的兩種擴充概念

n8n 的擴充分兩條線，這本手冊兩條都收：

  • Community Node：畫布上多一顆節點。你在 workflow 裡拉出來用（例：Puppeteer 抓網頁、ElevenLabs 產 TTS）。npm 上的 n8n-nodes-* 套件全部屬於這一類，2026-08 已破 500 個 package、5,800+ 顆 skill 級單元。
  • AI Agent Skill / MCP Server：給你的 AI（Claude／Cursor／Windsurf）多一項能力。掛上 n8n-mcp 之後，你講「幫我建一支 workflow」，AI 直接呼叫 n8n API 幫你做。這一類是「教 AI 怎麼跟 n8n 對話」，跟 workflow 本身沒關係。

兩種對「能自動化什麼」都有加成：Community Node 是幫「n8n 本人」多會一件事；MCP server 是幫「開 n8n 的你」少做一件事。

怎麼裝（3 分鐘版）

裝 Community Node

  1. 打開 n8n Settings → Community Nodes

    需要管理員權限。雲端版（n8n.woowtech.io）預設關閉自裝，請洽 WoowTech；本地 add-on 或自架 n8n 開起來就有。

  2. 按 Install a Community Node，貼上 npm package name

    例：n8n-nodes-mcp、n8n-nodes-puppeteer、@elevenlabs/n8n-nodes-elevenlabs。勾同意「使用第三方套件的風險」，按 Install。

  3. Reload n8n（或等它自動重啟）

    裝完在 workflow 編輯器的節點抽屜搜尋節點名稱，出現就成功。看不到？看 Executions → Errors，常見是套件相容性擋掉了。

  4. 拉節點試跑一次

    官方 template 或該 repo 的 README 幾乎都附最小可跑範例，貼 credentials 進去試看看。

裝 MCP Server（給你的 AI 用）

在 Claude Code／Cursor／Windsurf 的 settings.json／MCP config 加：

{
  "mcpServers": {
    "n8n-mcp": {
      "command": "npx",
      "args": ["-y", "n8n-mcp"],
      "env": {
        "N8N_URL": "https://n8n.woowtech.io",
        "N8N_API_KEY": "<你的 API key，在 n8n Settings → API 建立>"
      }
    }
  }
}

存檔重啟 AI 客戶端，就會看到 create_workflow、list_workflows 等工具出現。提示詞庫裡有 44 條可直接複製的 prompt。

提示：MCP server 通常不動 n8n 本身——它只是幫 AI 打 API。所以你可以在自架、Cloud、任何 n8n 實例上用，包括 n8n.woowtech.io 開帳號給你之後。

n8n MCP Servers · 給你的 AI 一個 workflow builder

MCP server 是「教你的 AI 怎麼跟 n8n 講話」的一段程式。掛好之後，你在 Claude／Cursor 講一句「幫我做一支 workflow」，AI 直接透過 n8n REST API 幫你 create／activate／debug。這一類目前最活的三顆：

czlonkowski/n8n-mcp

22.7k ★ · MIT · 極活躍（1,193 commits）

目前 star 最高的 n8n MCP，功能最完整：Core Tools 7 顆（node search／validation／template 探索／docs），Management Tools 16 顆（workflow CRUD、execution、folder、credential、audit、health）。覆蓋 2,541 個 n8n 節點（832 core + 1,709 community）99% property。

npx n8n-mcp

安裝也支援 Docker（ghcr.io/czlonkowski/n8n-mcp）、npm 安裝到本機、Railway 一鍵。2026 首選。

makafeli/n8n-workflow-builder

540 ★ · MIT · 活躍（56 commits）

更輕量的選擇：15 顆 tool 分 5 類（Core Workflow、Lifecycle、Advanced、Execution、Organization）。sweet spot 是 create_workflow_and_activate 一步到位、generate_audit 一鍵安全稽核。給不需要 node search 的中階用戶。

npx @makafeli/n8n-workflow-builder

TypeScript 撰寫、CI 完整、issue 回覆快。個人／小團隊起手推薦。

salacoste/mcp-n8n-workflow-builder

229 ★ · MIT · 多實例支援

17 顆 tool（8 workflow + 4 execution + 5 tag + 6 credential），特色是 Multi-Instance Support：一個 MCP server 同時管 dev／staging／prod 三個 n8n，AI 自動路由。適合有多環境的中型團隊。

38+ 頁詳細文件、credential 環境隔離做得細——需要多環境部署走這顆。

ifmelate/n8n-workflow-builder-mcp

≈200 ★ · 支援 VS Code／Cursor／Claude Code

強調 「agent mode」——AI 依你的自然語言 prompt 反覆迭代，自動 create → run → 觀察錯誤 → 修改。跟 IDE 內的 AI coding 體驗最一致。

適合已經在 Cursor 或 VS Code 寫 code 的工程師。

相容性須知

Community Node／MCP server 在你的環境跑不跑得起來，常見卡在三件事：

  • n8n 版本：node 通常 pin 某個 n8n minor 版本區間。WoowTech n8n.woowtech.io 目前是 v2.32.7 Community Edition，安裝前看 node README 的 peerDependencies。
  • Node.js 版本：node 用了新語法（例：optional chaining、top-level await）而你的 n8n 跑在較舊 Node.js 就會爆。HAOS add-on 版預設 Node 20，通常沒事。
  • 額外服務依賴：例如 Puppeteer 需要 Chromium binary，n8n Docker image 沒帶——要自己加 Dockerfile 或用 n8n-nodes-puppeteer 的獨立 image。

MCP server 相容性簡單：只要你的 AI 客戶端（Claude Code／Cursor／Windsurf）支援 MCP 就能用，跟 n8n 版本沒直接關係（它是打 n8n API）。

觀念：挑第一準則不是 star 數，是「這顆的作者活不活」——最近 3 個月有沒有 commit、issue 有沒有回覆。

安全守則

注意：Community Node 是可以執行任意程式碼的 npm 套件，MCP server 是能呼叫你的 n8n API的 process。裝之前想清楚。
  • 先讀 README，再 install：不是每顆都會標寫得清楚要哪些 credential、會發哪些請求。看不懂就叫 Claude 幫你讀一遍。
  • Production 環境釘版本：package.json 用 n8n-nodes-xxx: 1.2.3 而不是 ^1.2.3，避免上游改壞你無感升級。
  • MCP server 用 scoped API key：n8n API key 建議建一支專給 MCP 用，權限限制到「特定 workflow tag」或 read-only。不要用 admin key。
  • 看貢獻者：只有 1 個 contributor 的 node 要有心理準備——他停更了就沒有下一版。生產環境用有維護組織的（官方、企業）比較安全。
  • 裝完做 audit：MCP server 都有 generate_audit 工具，跑一次看有沒有新裝的節點洩漏什麼。

SKILL.md 規格速查（AI Agent Skill 用）

如果你要寫自己的 AI Agent Skill（給 Claude／Cursor 用），Anthropic 的 SKILL.md 規格是目前業界事實標準。最小骨架：

n8n-workflow-review/
└── SKILL.md          ← 唯一必要檔案

# SKILL.md 內容
---
name: n8n-workflow-review
description: 使用者傳 n8n workflow JSON 時，做結構檢查——
  找 dangling connection、缺 credential、明顯效能地雷。
  也在使用者問「這支 workflow 有問題嗎」「幫我 review」時觸發。
---

# n8n Workflow Review

（給 agent 看的做法說明，寫得像教新同事）
欄位必填說明
name是小寫英數與連字號，1–64 字元。
description是做什麼＋何時用。AI 靠這行決定要不要載入，把使用者會講的話寫進去。
license / compatibility / allowed-tools否授權、相容性標注、工具白名單等選填欄位。

慣例：SKILL.md 保持精簡，附件放 references/、scripts/、assets/，用到才讀，避免吃爆 AI 的 context。

提示：寫給 n8n 用的 skill 通常會描述「什麼 workflow pattern → 哪個 MCP tool」的映射；不寫成 skill 也可以，寫在 提示詞庫裡當範例是最輕量的做法。

常見問題

裝完 Community Node 沒出現在節點抽屜？
最常見兩個原因：（1）沒 reload n8n（或 add-on 沒重啟）；（2）版本不相容——看 Settings → Community Nodes 有沒有紅色錯誤訊息。實在不出來，去該 node 的 GitHub issue 搜同樣症狀，通常有解。
Community Node 會不會拖累 n8n 效能？
每顆節點都會佔 memory（class 常駐），裝 50+ 顆會讓 n8n 啟動變慢 5-10 秒。原則：常用的留著、試玩過不用的就 uninstall。做 audit 的時候一併檢視。
MCP server 需要一直開著嗎？會不會很吃資源？
MCP server 是 stdio 通信的短命 process——你的 AI 客戶端啟動時它才跑，關掉就停。CPU／記憶體用量幾乎為零，掛著沒差。
WoowTech 的 n8n.woowtech.io 可以自己裝 community node 嗎？
預設不能——雲端多用戶環境，加 node 會影響所有客戶。有需求請開 ticket，WoowTech 評估後統一裝（通常會依社群評價 + 安全審核決定）。要完整自主權請走 HAOS add-on 模式（見 銷售手冊）。
可以只用 npm 套件的 skill／node 名字打 star 追蹤，不裝嗎？
可以。npm 有 favorites、GitHub 有 star、awesome-n8n 有 issue 訂閱——先「收藏、看趨勢」，需要用了再裝，是最省心的策略。
寫了新的 community node 或 skill 想上架？
Community Node：npm publish 加上 keywords: ["n8n-community-node-package"]，n8n 官方會自動收錄。AI Agent Skill：push 到 GitHub，投稿到 topics/claude-skill；夠成熟的話 PR 到 awesome-n8n 或對應 skill 索引。
