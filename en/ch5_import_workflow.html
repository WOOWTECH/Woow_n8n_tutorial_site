Chapter 5

從 n8n.io 找 JSON 貼進來

上一章我們用了 n8n 內建的 Templates gallery，那是官方精選；但真正海量的分享大廣場是 n8n.io/workflows，社群幾千個 workflow 在那邊等你 copy。這章教你怎麼撈、怎麼「複製 JSON」、怎麼安全貼進 Woow n8n，還有貼進來之後 90% 新手會忘掉的那一步。

為什麼還要學這個

第 4 章教了你在 n8n workspace 內按左側「Templates」直接叫出來的那個 gallery——那份清單是 n8n 官方選過的、少而精。可是你在公司實際會碰到的需求常常很偏：

  • 「加拿大 GST/PST 稅務 API 撈完寫進 Airtable」
  • 「Notion 資料庫變動就發 Line Notify」
  • 「客戶填了 Typeform，資料丟 HubSpot 再開 Slack 頻道」

這種偏門組合，內建 gallery 通常沒有；但 n8n.io/workflows（也就是完整的社群分享網站）幾乎都找得到，因為過去五年有一堆歐美工程師把他們公司的 workflow 匿名化分享上去。這章就是教你怎麼從那個大廣場撈一份 JSON、貼進 Woow n8n 開始用。

觀念：ch4 的 Templates 是「n8n 內建版本」，這章的 n8n.io/workflows 是「社群版本」。兩個都會用，遇到冷門需求先來這裡撈。

workflow JSON 到底是什麼

你在 n8n canvas 上拉的每一個 workflow，實際上背後就是一個 JSON 檔。這個 JSON 記錄了三件事：

JSON 裡有什麼對應 canvas 上的什麼會不會跟著走
nodes 陣列（每個節點的類型、位置、參數）你在畫布上看到的方塊會
connections（哪個節點接到哪個節點）方塊之間的線會
節點的欄位設定（例：Slack 要傳到哪個 channel、Sheet 的 tab 名字）你點進節點看到的 Parameters會
credentials（帳號密碼、OAuth token、API key）節點頂端「Credential to connect with」下拉選單不會！

最關鍵一列在最後：credential 的機密內容（密碼、token、API key）不會跟著 JSON 走。分享 workflow 給別人不會不小心把你自己的 API key 洩出去；反過來，別人分享給你的 workflow，你也不會偷到他的帳號——你要自己接你的。JSON 裡通常只會殘留一小段像 credentials: {"slackApi": {"id": "abc123", "name": "Slack account"}} 的引用資訊，那個 id 是原作者環境裡的 ID，貼到你這邊會顯示「credential not found」紅字——這正是提醒你要接自己的那組。這是 n8n 設計上就想清楚的事，安全這一關幫你把好了。

提示：「credential 不會跟著走」這件事，在第 13 章會再深入講原理。目前你只要記住：貼進來的 workflow，credential 一定要重接一次。

從 n8n.io/workflows 撈一份貼進 Woow n8n

  1. 打開瀏覽器到 n8n.io/workflows

    網址直接輸入 https://n8n.io/workflows/。這是 n8n 官方主站上、與 workspace 內建 gallery 分開的「社群分享大廣場」，幾千個 workflow 全部在這裡列。第一次來會被首頁塞滿嚇一下，正常。

  2. 用關鍵字或分類過濾

    頁面上方有搜尋列，直接打你想要的關鍵字，例如 Airtable、Notion、Line、Typeform。左邊還有 filter：可以照「App」（用到哪些服務）、「Category」（AI、Marketing、Sales、DevOps 等）縮小範圍。想找 AI-flavor 的就打「Airtable」再左側勾「AI」。

  3. 點進去看細節

    每個 workflow 卡片點進去會看到三件事：Preview（節點連接圖，讓你一眼看出邏輯有多複雜）、Description（作者寫的用途說明）、使用到的節點 / 需要的 credentials 清單。花 30 秒把這頁看完，比複製回去再拆解快十倍。

  4. 用 ch4 教過的 5 個訊號判斷值不值得抄

    還記得第 4 章教的五個「這模板可靠嗎」訊號嗎？作者是誰、更新日期、節點數量合不合理、描述夠不夠具體、需要的 credential 你有沒有——一樣照這五點掃一次。特別注意「最後更新日期」：n8n.io 上有些 workflow 是 2020 年的，那個時代的節點很多已經改名或退場，貼進來可能一堆紅色 error。

  5. 按右上角「Use for free」→「Copy template to clipboard」

    看中一個以後，右上角有個綠色 Use for free 按鈕，點下去會展開選項。裡面有 Copy template to clipboard（把整份 workflow JSON 複製到剪貼簿）——這就是我們要的。點下去畫面會閃一下「Copied!」的小提示。這時候剪貼簿裡就是一大坨 JSON 了。

  6. 切回 Woow n8n 的分頁

    回到你開好的 n8n.woowtech.io 分頁（沒開請照第 1 章來）。任選一個現有的 workflow 打開，或者按左側「+ Add workflow」開一個全新的空白 workflow。建議開新的：貼進來的節點會直接落在你目前打開的 workflow 上，開新的比較不會跟現有工作攪在一起。

  7. Canvas 空白處右鍵 → Paste，或直接按 Ctrl+V

    滑鼠移到 canvas 中間的空白處（不要點在任何節點上、也不要點在頂端的 workflow 名字欄位裡），按 Ctrl+V（Mac 是 Cmd+V）。咻！——所有節點連帶連線、連帶原本的相對位置，全部一次落到你的 canvas 上。

  8. 另存新檔並改名

    左上角 workflow 名字預設會用 n8n.io 上原作者取的英文名。點下去改成中文（例：「加拿大稅務同步 Airtable」）方便你日後在 Workflows 清單找。右上角記得按一下 Save（或 Ctrl+S），不然重新整理就沒了。

注意：不要在按 paste 之前先手癢按 Activate（右上角那個綠色 toggle）。貼進來的 workflow 節點一堆還沒接你自己的 credential，開起來只會滿螢幕 error。先貼、再接 credential、再手動 Execute 測一次，最後才 Activate。

如果是朋友（或 GitHub Gist）給你 JSON 檔

不一定要走 n8n.io，同事在 Slack 傳給你 my_workflow.json、或看到某位 YouTuber 把 workflow 貼在 GitHub Gist——這些場景一樣能用。有兩種姿勢：

姿勢一：貼文字（推薦，適合小的 workflow）

  1. 打開那個 JSON 檔

    用 VS Code、記事本、任何文字編輯器打開，或者 GitHub Gist 頁面按「Raw」看原始 JSON。

  2. 全選複製

    Ctrl+A 全選，Ctrl+C 複製。整段 JSON 進到剪貼簿。

  3. 回 n8n canvas 空白處貼上

    跟上一節第 7 步一模一樣：空白處按 Ctrl+V。

姿勢二：匯入檔案（適合幾百 KB 的大 workflow）

  1. 打開任一 workflow，找到右上角的三點選單「⋮」

    就在 workflow 名字旁邊、Activate toggle 附近。點下去展開一個選單。

  2. 選「Import from File...」

    會跳出檔案選擇器。找到你下載的 .json，選好按開啟。同一個選單裡還有 Import from URL...，如果 JSON 放在 GitHub Gist 的 raw URL、或某個 public 網址，貼網址進去比下載檔案更快。

  3. 節點會全部貼進來

    跟複製貼上效果一樣，只是不用打開檔案再全選。大 workflow（幾百個節點）用這個比較不會卡剪貼簿。

提示：兩種姿勢功能完全等價，看你順手。90% 的情況「複製 JSON 貼上」比較快；只有拿到超大檔或不想打開文字編輯器時才走 Import from File。

貼進來之後最容易忘的一步：接自己的 credential

這是 90% 新手第一次匯入 workflow 都會漏掉的一步。剛剛講過 credential 不會跟著 JSON 走，所以貼進來的每個節點裡，「Credential to connect with」下拉都是空的（或紅字寫著找不到）。

怎麼看出哪些節點需要接？

  • 節點頂端會有紅色框或紅色驚嘆號小圖示——這是 n8n 在明講「這個節點還沒準備好」。
  • 點進節點看 Parameters 面板，最上面的 credential 下拉會顯示 「No credentials selected」 或 紅底的 error 訊息。
  • Canvas 上有整條 workflow 的視覺 hint：紅色節點連成一串，一眼就掃出來要修哪些。

怎麼接？

  1. 點紅色的節點打開 Parameters

    點該節點兩下（或右側面板單擊），節點內容展開。

  2. 找到最頂端的 credential 下拉

    下拉裡如果有你之前設過的同款 credential（例：你之前設過一組 Slack OAuth），選它就好。如果沒有，選最下面的 Create New Credential。

  3. 按提示填帳號 / 授權 / 貼 API key

    每一家服務的 credential 表單不一樣（Slack 是 OAuth、Airtable 是 Personal Access Token、HTTP Request 可以什麼都不填）。第 13 章會把每種 credential 類型講一遍，這裡先按 UI 提示走。

  4. 存檔、回 canvas 看紅色消失了沒

    設好按 Save，回 canvas 那個節點應該從紅框變回正常灰框。全部節點都變灰以後，才可以按 Execute Workflow 測試。

注意：如果貼進來的是一個很大的 workflow（20+ 個節點、串了 5-6 家 SaaS），接 credential 這件事可能要花你半小時。這是預期值，不是你做錯——別人分享的 workflow 越豐富，你要接的 credential 就越多。

匯入舊版 workflow 的常見坑

n8n 每幾個月會升一次大版本，節點會改名、參數會重排。從 n8n.io 撈到一個 2021 年的 workflow 貼進 Woow n8n（目前跑的是相對新的版本），最容易撞到下面幾種問題：

症狀原因怎麼救
某個節點名字紅字，寫「Unknown node type」 n8n 升級後那個節點改名了。經典例子：Function 節點在新版被 Code 節點取代 刪掉那個節點，從節點抽屜找新名字（Code）重拉一個，把原本的 JavaScript 貼進去
節點紅框，錯誤說「Node type not found: n8n-nodes-xyz」 作者用了「community node」（社群裝的第三方節點），你這台 n8n 沒裝 需要管理員裝 community package。這超出本章範圍，先跳過或找沒用 community node 的替代 workflow
Webhook 節點的 URL 看起來像別人的網址 Webhook 節點會自動用「你這台 n8n 的 base URL」產生 URL，貼進來會 重新產生一個屬於你的新 URL——原作者的 URL 打不到你這裡（好事，是隔離） 打開 Webhook 節點看你自己的 Production URL，把新 URL 貼給要 call 你的系統（例：Line Bot、Typeform）
某個節點參數欄位少了東西、或多了新欄位 節點升級後 schema 改了。新欄位通常有預設值不會炸；舊欄位可能已經沒作用 點該節點按 Execute Node 手動跑一次，看錯誤訊息告訴你哪個欄位有問題再補
整個 workflow 貼進來但畫面看起來只有一半 節點位置遠在 canvas 的右下角視野外 按 canvas 右下角控制列的「Fit to view」按鈕（放大鏡對準畫面那顆），或直接按數字鍵 1 縮到全畫面就看到全貌了

反過來：匯出你自己的 workflow 給別人

做好一個實用 workflow 想分享給團隊或朋友？步驟也一樣簡單：

  1. 打開要匯出的 workflow

    在 Workflows 清單點進去，任何一個都行。

  2. 右上角三點選單「⋮」→「Download」

    選 Download 會直接下載一個 .json 檔到本機。檔名預設就是 workflow 的名字。

  3. 把檔案（或整段 JSON 文字）給對方

    用 Slack、Email、Google Drive 都行。對方拿到後照這章教的方式貼進他的 n8n。

危險：雖然 credential 不會跟著 JSON 走，但你在節點參數欄位裡如果手癢直接把 API key 貼在明文欄位（例：某個 HTTP Request 節點的 header 硬寫 Authorization: Bearer sk-xxx），這個是會跟著 JSON 走的。分享前檢查每個節點的 Parameters，凡是 API key、密碼、token 都要走 credential 系統，別寫死在欄位。

常見問題

能不能自動同步 n8n.io 上原作者的更新？
不行。你按 Copy 那一刻的版本就是你的版本，之後原作者改了、修 bug 了、加新節點了，你這邊都不會自動吃到。想追新版就手動再回去 n8n.io 撈一次、跟你手邊的比對差異。這也是為什麼真正在用的 workflow 建議另存新檔改中文名——你已經把它當自己的東西維護了。
Import 進來會不會覆蓋掉我現有的 workflow？
預設不會覆蓋，是「新增」——匯入永遠是「多一個 workflow」。唯一會 merge 的情況是：你已經打開一個 workflow 在 canvas 上，這時候 Ctrl+V 貼進來的節點會加到目前這個 workflow 的 canvas 上跟原本的節點並存。想避免混在一起，先按左側「+ Add workflow」開一個空白的，再 paste。
Copy JSON 之後貼進 n8n 卻變成純文字，發生什麼事？
你 paste 時滑鼠焦點在錯的地方了。最常見兩種：(1) 點到頂端 workflow 名字的輸入框，JSON 就變成 workflow 的名字（笑）；(2) 點到某個 sticky note 或某個節點內的欄位，JSON 就被塞進那個欄位。解法：先在 canvas 空白處單擊一下讓焦點回到畫布，再按 Ctrl+V。
一次能 import 幾個 workflow？有沒有 Bulk import？
UI 上一次只能匯入一個 JSON 檔（或貼一份 JSON）。想批次搬 workflow 有兩條路：(1) 一個一個 paste，笨但保險；(2) 用 n8n 的 CLI 或 REST API 批次 import——這是進階操作，需要有 API key 或 shell 存取權，附錄 C 會提到概觀。日常從 n8n.io 抓的量單筆貼就夠。
怎麼備份我所有的 workflow？我怕哪天 n8n 掛了
短期：每個重要 workflow 都手動 Download 一份 JSON 存到 Google Drive 或 GitHub。長期：走 CLI 或 REST API 批次匯出，可以寫個 script 每晚跑一次。這在附錄 B與附錄 C 的「底層架構」章節會講設定細節。Woow n8n 的 admin 也有做整站備份，但自己另存一份總是保險。
從 n8n.io 抓下來的 workflow 商業使用有版權問題嗎？
n8n.io/workflows 上分享的 workflow 預設就是給人自由使用、改造、內部商業用途的（作者上傳時已同意）。你不用付版權費、也不用註明來源。但如果你要把「別人的 workflow 二次封裝賣錢」就要看原作者 profile 有沒有特別聲明。日常公司內部用，安啦。
我改了貼進來的 workflow 之後怎麼分享回社群？
n8n.io 有「Submit a workflow」的入口（帳號登入後），可以把你的 JSON 貼上去、寫描述、選分類、送審。審過就會出現在大家搜尋列表裡。這超出這章範圍，之後第 6 章會延伸講改別人 workflow 的節奏，貢獻回社群屬於進階題。
