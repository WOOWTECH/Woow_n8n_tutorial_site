第 1 章

什麼是 n8n？跟 Zapier/Make 差在哪

你每天在做的那些重複勞動——早上把行事曆貼進 Slack、把表單收件抄進試算表、看到某封信就轉發、月底統計上個月銷售——其實都可以外包給一個叫 n8n 的自動化工具。這章不用你動手，帶你認識它是什麼、跟你可能聽過的 Zapier / Make / Power Automate 差在哪，還有 Woow 為什麼選它。

為什麼要學這個

你先想一下今天上班到現在做了幾件「其實電腦可以自己做」的事：

  • 早上打開 Slack，把今天要開的會議一條一條貼在部門頻道，讓大家知道你人跑哪去了。
  • 客戶填完 Google 表單，你打開試算表把資料抄過去，順便寫一封確認信給對方。
  • 信箱裡出現某位 VIP 客戶的來信，你趕快轉發給業務主管，怕漏掉。
  • 月底了，你打開三家平台的後台，抓上個月銷售數字，貼進報表 Excel，再截圖給老闆。

這四件事有個共通點：規則是死的、資料是活的。步驟每次都一樣，只有裡面的內容在變。這種事情就是自動化（Automation）工具最擅長的——你把「規則」告訴它一次，之後它每天自己跑，不會漏、不會忘、也不會請病假。

觀念：自動化不是取代你，是把你從「複製貼上」裡救出來。省下來的時間，你才有力氣去想真正需要人判斷的事——談客戶、寫提案、想新產品。

公司這次選的自動化工具叫 n8n（唸 "n-eight-n"，是 "nodemation" 的縮寫）。這章讓你先認識它是什麼、後面 21 章帶你動手做出真的會跑的流程。

n8n 是「拼樂高的自動化」

如果要用一句話講 n8n，那就是——拼樂高的自動化工具。

樂高每一塊積木都有固定形狀跟凸點，你把它們拼起來就是一台車、一棟房子。n8n 也一樣：它預先準備好幾百塊叫「節點（Node）」的積木，每一塊會做一件事——

  • 有一塊叫 Gmail，會讀你收到的信；
  • 有一塊叫 Google Sheets，會寫一列進試算表；
  • 有一塊叫 Slack，會傳一則訊息到你指定的頻道；
  • 有一塊叫 Schedule Trigger，會每天早上 8:00 自動戳一下。

你要做的事就是——在畫面上把積木拉出來、用線接起來。線是資料流的方向：Gmail 讀到的信會沿著線流到下一塊積木。

提示：這個「畫面上拉節點、拉線接起來」的畫布，n8n 叫它 Canvas（畫布）。你 90% 的操作都在這裡完成，不用寫任何程式碼。到第 8 章你就會第一次拉出這樣的流程。

那跟寫程式差在哪？寫程式的話，你得自己想「怎麼用 Gmail API 拿信、要傳什麼 header、拿到 JSON 之後怎麼 parse」；n8n 已經幫你把這些細節通通包在那塊 Gmail 積木裡了。你只要在旁邊填「用哪個帳號」「抓最近幾封」「要不要限定寄件人」就好。

觀念：99% 的積木都準備好了，你只是選要用哪一塊、怎麼接。真的沒現成的（機率很低），也可以用 Code node（第 20 章）寫幾行程式補洞——但前 15 章你完全不用碰程式。

具體來說，它能幫你做什麼

用剛才「早上貼行事曆到 Slack」當例子，翻譯成 n8n 積木就是：

  1. Schedule Trigger 積木：每天早上 8:00 戳一下

    這是流程的起點。它的工作只有一個——時間到了就發動下游。你可以設每小時、每天固定時間、每週一 9:00、每月 1 號等等。

  2. Google Calendar 積木：抓今天所有事件

    用你的 Google 帳號連上，跟它說「幫我抓今天 00:00 到 23:59 的所有事件」。它會沿著線把一筆一筆事件（名稱、時間、地點）送給下一塊。

  3. Slack 積木：把清單傳到指定頻道

    接住上一塊送來的事件清單，組成一則訊息，貼到你 Slack 的某個頻道（或私訊給你自己）。

三塊積木、兩條線，就搞定「每天早上自動貼行事曆」這件事。這個具體怎麼做，我們會在第 8 章手把手帶你拉一次。這裡先讓你有個感覺：一條 workflow 通常就三到七塊積木，長不到哪去。

n8n vs Zapier vs Make vs Power Automate

市面上做這類事的工具不只 n8n。你可能聽過或用過其中一家。這張表把四家一起攤開比：

比較項目 n8n Zapier Make（原 Integromat） Power Automate
畫面型態 Node graph 節點圖（左右流） Multi-step 上下步驟表 Scenarios 圓點連線 Flow 直式流程
費用模式 Community 版自架完全免費；Cloud 版月費 每個 task 計費（每執行一個節點就扣一次） 每個 operation 計費（比 Zapier 便宜） 按 flow 數 + 使用者授權
可自訂程度 有 Code node（JS/Python），什麼都能改 有限，只有 Code by Zapier 附加功能 有 Functions 模組，但受限 受限，需要靠 Power Fx 表達式
資料視覺化 每個節點都能點開看 JSON 進出 只顯示欄位對照 Bundle 視覺化不錯 需要 debug 模式
社群 & 模板 幾千個公開 workflow、開源 幾千個 Zap 模板 模板較少 企業 template 為主
資料儲存位置 自架時資料都在自己伺服器 Zapier 雲端 Make 雲端 微軟雲端
適合誰 技術友善公司、要客製、要省錢 個人使用者、小團隊、只用主流 SaaS SMB、想要視覺漂亮 已經用 Microsoft 365 的企業
注意：Zapier 好用，但每執行一個節點都在算錢。一條有 5 個節點的 workflow 每天跑 100 次，一個月就 15,000 tasks，很快超過免費額度。n8n Community 版自架的話，這條 workflow 一天跑 100 萬次都是 0 元。

簡單記結論：個人偶爾串一下用 Zapier、公司要大量跑用 n8n。你今天在公司之所以會看到這本手冊，就是這個理由。

Woow 為什麼選 n8n

公司評估過 Zapier、Make、Power Automate 之後，最後決定用 n8n。理由不外乎這幾個：

  1. 資料留家裡

    我們選的是 Community edition（社群版）自架，n8n 跑在自己的伺服器上。客戶資料、內部訊息、報表都不會流到別家公司的雲端。這對接觸客戶名單、財務數字的工作很重要。

  2. 費用可控

    Community 版完全免費、不限使用者、不限 workflow 數、不限執行次數。伺服器成本就是我們原本 IT 費用的一小部分，跟 Zapier / Make 每月幾百到幾千美元比起來省很多。

  3. 節點種類最齊全

    n8n 官方 400+ 個整合節點，加上社群提供的節點，主流 SaaS 幾乎都有。沒有官方的，還有 HTTP Request 節點可以打任何 REST API（第 4 章會示範怎麼找）。

  4. 可以寫程式補洞

    複雜到現成節點做不到的資料處理，可以放一個 Code node（第 20 章）寫幾行 JavaScript 或 Python。這個「逃生口」是 Zapier / Power Automate 給不了的自由度。

  5. AI Agent 節點原生支援

    n8n 內建 LangChain 系列的 AI Agent（第 21 章）節點——直接把 GPT / Claude 塞進 workflow 當一個「會判斷」的節點，做客服前哨、資料分類、報表摘要都好用。而且是走公司 LiteLLM gateway 統一管理，AI 費用集中一個地方看。

  6. 跟公司既有生態合得來

    Woow 有 Home Assistant、有 Podman、有 k3s。n8n 用 Docker/Podman 一行指令就跑起來，還能透過 Webhook 跟 HA 互相打招呼（第 22 章）——例如 HA 偵測到會議室有人就叫 n8n 幫忙開 Meet。

它不適合的場景

誠實講，n8n 也不是萬能。以下情境你硬要用 n8n，會踩雷：

不適合的場景為什麼該用什麼
高頻交易（每秒幾百次） n8n 一次執行有啟動成本，不是做即時毫秒級運算的引擎。 寫成專屬服務（Go / Node.js）
需要 SLA 99.99% 的關鍵營運流程 Community 自架版沒有官方保障。掛掉靠公司 IT 修。 Enterprise 版或商用 iPaaS
大量 CPU / 資料運算 n8n 的 Code node 適合輕度處理，不是拿來跑 ETL 幾千萬列的引擎。 Airflow、Dagster、dbt
非常複雜的商業邏輯 一條 workflow 超過 30 個節點、有多層巢狀分支就會失控。 該寫成正式應用程式了
面向終端使用者的 App n8n 是後台自動化，不是給客戶點的前端介面。 Retool、AppSmith、自己刻
觀念：會不會「所有東西都用 n8n 做」？——不會，也不該。它是膠水，把你已經在用的工具接起來；它不是用來取代那些工具本身。

常見疑慮（開始前想清楚）

還沒動手之前，可能你腦裡有這些問號。先在這裡回答，免得你邊做邊分心。

  1. 公司想給我 Zapier 帳號比較好吧？

    Zapier UX 更手把手沒錯，但一個常見的行銷團隊 use case（每天處理 500 筆表單 × 每筆 3 個 task = 45,000 tasks/月）Zapier 起碼 Team 方案月費幾百美元起跳。Woow n8n 自架版跑同樣的量是 0 元。學 n8n 對你個人來說也是履歷上的加分——它是目前市面上最紅的開源自動化平台。

  2. 我完全沒寫過程式，我行嗎？

    行。本書前 15 章不用寫任何程式。你只要會用滑鼠拖節點、在欄位填字。第 20 章的 Code node 是進階選項，就算你永遠不用也能做出 80% 的自動化。

  3. n8n 掛了誰負責？

    IT 部門負責平台運維（伺服器、備份、升級）。你負責的是「workflow 內容」——就跟你不用管 Google Docs 的伺服器一樣，你只要專心把文件寫好。真的掛了就開 IT 單。

  4. 別的部門會看到我的 workflow 嗎？

    看你放哪裡：放 Personal folder（個人資料夾）只有你自己看得到；放 Workspace（工作區）就是團隊共用，同 workspace 成員都能看和編輯。存放位置和權限的細節在第 13 章會講。

  5. 我做壞了會不會弄爆線上系統？

    n8n 有 Manual 執行（手動觸發）跟 Active/Inactive 開關兩層保護。你在 Inactive 狀態下想試幾百次都行，只有你按 Activate 才會開始按排程或 Webhook 觸發跑。第一次上線建議先 Manual 跑幾次確認，再打開 Active。

常見問題

n8n 是免費的嗎？

看版本：

  • Community edition（社群版）：完全免費、開源、自架，我們公司走的是這條路。不限使用者、不限 workflow、不限執行次數。
  • Cloud edition（雲端版）：n8n 官方託管，月費從 US$20 起，按每月 executions 數收費。你不想自架的話可以選。
  • Enterprise（企業版）：加 SSO、SAML、audit log、SLA 支援，價格談。

Woow 用的是 Community 版自架在 n8n.woowtech.io，你完全不用擔心「用多了要不要加購」的問題。

那跟 IFTTT 一樣嗎？

方向類似但等級差很多。IFTTT（"If This Then That"）是消費者取向的迷你自動化——「太陽下山開燈」「按讚就存到 Pocket」，一條規則只有一個觸發、一個動作。n8n 是專業級的：一條 workflow 可以有幾十個節點、分支、迴圈、錯誤處理、AI 判斷。IFTTT 是玩具、n8n 是工具。

我一定要學程式嗎？

不用。本書前 15 章教的所有東西都是「拖節點、填欄位」的層級，你點滑鼠就行。到第 14 章 Expression會出現一點點類似 {{ $json.email }} 這種語法，但那也是照著範例套。真的想深入的話再看第 20 章 Code node。

AI 節點是不是要另外付錢？

n8n 節點本身免費，但你叫 AI 幫你想事情的時候，模型（OpenAI GPT、Claude、Gemini 等）是外部服務、要付 API 費用。Woow 這邊統一走公司內部的 LiteLLM gateway，所有 AI 呼叫集中計費、集中管理，你在 AI Agent（第 21 章）裡選 Woow LiteLLM 的 credential 就好，不用自己申請 OpenAI 帳號。

n8n 跟 Make 都是視覺化拖節點的，長得有像嗎？

畫面風格接近但邏輯不同。Make 是圓點連線、資料是一包一包的 bundles；n8n 是節點左右流、資料是 items 陣列，可以在節點上直接點開看每一筆 JSON。用過 Make 的人會覺得 n8n 更好 debug——因為每個節點的輸入輸出都攤在眼前。

我的 workflow 資料會不會外流？

Woow n8n 是自架的（就在公司自己的伺服器上），你的 workflow 定義、執行歷史、credentials 全都存在公司伺服器裡，沒有跟 n8n 官方或任何第三方分享。credentials 用 AES 加密存資料庫。要出公司的資料只有你自己在 workflow 裡明確叫它出去（例如打 Slack、寄 Gmail）才會出去。

下一步做什麼？

去第 2 章登入 n8n.woowtech.io，拿到你自己的帳號、看看主頁長什麼樣。這章讀完你腦裡有輪廓就夠了——n8n 是「拼樂高的自動化」，公司選它是因為便宜、資料留家裡、可擴充。剩下的都是動手時的事。
