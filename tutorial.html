Woow n8n 入住指南

把重複工作外包給流程自動化

從打開 Woow n8n、用別人做好的 template、拉出第一支 workflow，一路帶到 Expression、Code node、AI Agent、Webhook。22 章＋ 3 附錄，每章 10 分鐘。銷售手冊、提示詞庫與 Skill 手冊在 資源總覽。

起步認識

01

什麼是 n8n？跟 Zapier/Make 差在哪

為什麼公司選 n8n、跟你可能用過的 Zapier/Make 差在哪、能替你省掉哪些重複勞動。

 02

打開 Woow n8n：登入與 5 分鐘介面導覽

打開 n8n.woowtech.io、拿到你的帳號、確認裝置能連進來、看完介面主要區塊。

 03

工作區長什麼樣

Canvas、節點抽屜、Executions、Templates、Credentials 一次認完不再迷路。

從別人做好的起步

04

從 Templates gallery 起步

n8n 已經有幾千個現成 workflow，直接抄別人做好的最快上手。

 05

從 n8n.io 找 JSON 貼進來

n8n.io/workflows 有海量分享的 workflow，複製 JSON 貼進來就是你的。

 06

動一動別人做好的：改欄位、換觸發、跑一次

拿別人 workflow 直接用是幻想。這章教你怎麼改成自己的用途。

動手做第一個

07

三種節點：Trigger / Action / Core

節點抽屜幾百個節點，其實就三類：開頭、做事、控制流程。

 08

第一個 workflow：早上把 Google 行事曆推 Slack

從零拉出一個實用 workflow：早上 8:00 把今天的行事曆推到 Slack。

 09

Item 是什麼？資料怎麼在節點間流動

n8n 的 item 觀念一次講清：一個節點吃幾個 item、下一個節點怎麼收。

 10

三種觸發：Manual / Schedule / Event

workflow 什麼時候會跑？手動、排程、外部事件三種選擇。

常用整合

11

熱門 SaaS 整合：Slack、Gmail、Google 表格與 Drive

上班族最常需要串的四家：Slack 通知、Gmail 寄信、Google 表格記錄、Drive 存檔。

 12

HTTP Request 節點：碰所有沒官方整合的 API

n8n 沒現成節點的服務，用 HTTP Request 節點自己打。80% 的自訂串接靠這個。

 13

Credentials 管理：金鑰、OAuth、跟同事分享的界線

workflow 要拿你的帳號密碼才能幫你辦事，這章教怎麼安全存、怎麼分享。

 14

Expression 入門：`{{ $json.field }}` 從這裡開始

節點欄位要抓上一個節點的資料時，靠 Expression。這章講最常用的五種。

流程控制

15

IF / Switch：條件分支

if 大於 100 走 A 分支、小於 100 走 B 分支——這章教視覺化寫條件。

 16

Merge / Split / Item Lists：處理多筆資料

同時處理很多筆、把多路合起來、把陣列拆開，這三種是 n8n 的資料水管。

 17

錯誤處理：Error workflow / Retry / Wait

workflow 半夜掛了怎麼救？這章教錯誤流程、重試與等待。

資料整形與重用

18

Set / Edit Fields：資料整形不寫程式

把上一個節點的 JSON 加欄位、改名字、重排——不寫程式版本。

 19

Sub-workflow：把常用邏輯抽成小工作流

同一段流程五個 workflow 都在用？抽成 sub-workflow 一改全改。

拔高進階

20

Code node：在 workflow 裡寫幾行 JavaScript

現成節點做不到的資料處理，Code node 給你逃生口。新手 copy-paste 就好。

 21

AI Agent：讓 workflow 有一個「會想的」節點

普通節點是規則機器人，AI Agent 是「有判斷力」的節點。做客服、資料整理超好用。

 22

Webhook：讓外部系統打進 n8n

表單填完、HA 觸發、Line 訊息進來——都靠 Webhook 節點打進 n8n。

附錄

A

設定速查

Executions 保留天數、Timezone、Log level、Personal 與 Workspace 設定的意義。

 B

常見錯誤排錯

節點紅色、Timeout、Credential 失效、429 Rate limit、Sub-workflow 找不到——症狀對照解法。

 C

底層架構好奇者向

Community vs Cloud vs Enterprise 差別、self-host 選擇、queue mode、資料庫。
