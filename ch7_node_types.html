第 7 章

節點四大家族：Trigger / Core / App / Cluster

前面六章你已經會登入 n8n、認得工作區、還會把別人做好的 workflow 抄過來改。從這章開始要動手拉自己的了——但在動手前，你得先看得懂節點抽屜。官方文件把節點分成四大家族：Trigger（開頭）、Core（內建流程／資料工具）、App（跟外部服務講話）、Cluster（AI Agent 這種「一個根節點掛一堆子節點」的群組結構）。前三個是傳統自動化的骨架，第四個是 2024 之後 LangChain 那一整包 AI 節點的新架構。這章讀完你看任何 workflow 都能兩秒歸類。

為什麼要先分類

你到第 3 章看過的節點抽屜——按 Canvas 空白處的 +、或右邊面板點 Add first step，那個從右邊滑出來的清單。裡面東西多到嚇人：

  • 官方節點 400+ 個（Slack、Gmail、Notion、Airtable、HubSpot、Stripe、GitHub…）
  • Core 節點 30+ 個（IF、Switch、Merge、Edit Fields、Code、Wait、HTTP Request…）
  • Trigger 節點另外還有一大排（Schedule、Webhook、每家 SaaS 都自帶一個 Trigger 版）
  • 再加上 AI／LangChain 系列一整包（AI Agent、Chat Model、Memory、Vector Store…）

你不用背這幾百個名字。真正需要的是——看到一個節點，兩秒內知道它屬於哪一類、能幹嘛。這樣看別人的 workflow 才不會霧煞煞，自己拉的時候才知道該去哪一區找。

提示：這章是純觀念章，沒有動手步驟。看完直接進第 8 章拉你的第一條 workflow，就會自然而然用到這四類節點的分工。

先講結論，一句話對照（對應官方 docs.n8n.io/integrations/builtin/ 底下的四個資料夾）——

  • Trigger（功能分類）= workflow 的「開頭」，決定什麼時候會跑；左邊沒輸入圓點
  • Core nodes（core-nodes/）= n8n 內建的流程／資料／通用工具（IF、Merge、Set、Code、HTTP Request、Wait、Schedule Trigger…）
  • App nodes（app-nodes/，官方也叫 Actions）= 每一家外部 SaaS 一個節點（Slack、Gmail、Notion…）
  • Cluster nodes（cluster-nodes/）= AI／LangChain 專用的群組節點：一個 root 節點（例：AI Agent）掛多個 sub-node（Chat Model、Memory、Tool、Vector Store）
觀念釐清：Trigger 是「功能角色」，Core／App／Cluster 是「官方檔案分類」。所以 Schedule Trigger、Manual Trigger、Chat Trigger、Webhook 這些 Trigger 節點的文件其實放在 core-nodes/ 底下——它們既是 Trigger（功能）也是 Core（分類）。這兩個維度會交叉，不是互斥的四選一。

下面四節分別細講。

Trigger 節點：workflow 的開頭

每一條 workflow 都需要一個起點。這個起點就叫 Trigger 節點——它決定「這條 workflow 什麼時候會跑」。你打開節點抽屜第一個看到的分類通常就是 On app event / On a schedule / When called by another workflow 這幾組，全部都是 Trigger。

Trigger 節點有一個很好認的視覺特徵：它左邊沒有輸入圓點。因為它是起點，前面沒東西可接。右邊有一個輸出圓點，把資料往下游送。

Trigger 節點什麼時候會跑典型用途
Manual Trigger 你按下 Execute Workflow 才跑 測試、開發、給人手動點的 workflow
Schedule Trigger 像 Cron，指定時間跑（每小時、每天 8:00、每週一…） 每日報告、每週彙整、每月結算
Webhook 外部系統打 URL 就跑 表單填完、Line Bot、HA 觸發、第三方 callback
App Event（Gmail Trigger、Slack Trigger…） 指定 SaaS 有事情發生就跑 收到 VIP 信件轉發、Slack 提到某關鍵字通知
Chat Trigger 使用者在 chat 介面打字就跑 AI Agent（ch21）做客服機器人時用
Execute Workflow Trigger 另一個 workflow 呼叫你就跑 被抽出來重用的 sub-workflow（ch19）
觀念：一個 workflow 可以有多個 Trigger。例如同一條「新客戶通知」既掛 Webhook（表單填完）、又掛 Schedule Trigger（每天 8:00 補跑一次）、還掛 Manual Trigger（測試時手動跑）——任何一個觸發都會讓整條 workflow 動起來。第 10 章會專門講三大類觸發時機的比較。

Trigger 節點的抽屜位置也很好認——n8n 進節點抽屜的第一頁預設就是 Triggers，你在 Canvas 空白處按 + 開始新 workflow 的時候，n8n 會直接引導你選 Trigger（因為沒 Trigger 就沒起點、workflow 根本跑不起來）。

App 節點（Actions）：跟外部服務講話的節點

四大家族裡數量最多的就是 App 節點——官方文件把它們放在 integrations/builtin/app-nodes/，UI 抽屜裡則會叫 Actions in apps。共通點是：每一個節點對應一家外部服務（SaaS、資料庫、雲端），節點內部封裝好那家 API 的所有操作。

如果你用過 Zapier，這個概念一模一樣——Zapier 每個 App 對應一個 Action；n8n 也是一家 SaaS 對應一個 App 節點。「App 節點」是官方檔案名稱、「Action」是抽屜 UI 標籤，兩個講的是同一件事，本教學混用時你不用糾結。

一個 Action 節點裡面通常有很多 sub-operation（子操作）。以 Slack 為例——

  • Send Message：傳訊息到指定頻道或人
  • Update Message：改一則已經傳出去的訊息
  • Delete Message：刪一則訊息
  • Get Channel：抓某個頻道的資訊
  • Invite User：邀某人進頻道
  • …還有 20 幾個其他操作

你不用一開始就記所有子操作。拉出 Slack 節點後，右邊 Operation 下拉選單會列所有選項，你要哪個選哪個。

Action 節點官方大概分成這幾大類，抽屜裡都能對號入座：

分類常見節點典型場景
Communication 通訊 Slack、Discord、Telegram、Email、Line 通知、群發、聊天機器人
Data & Storage 資料儲存 Google Sheets、Airtable、Notion、Postgres、Redis、MongoDB 寫入表格、查資料庫、做資料流
Productivity 生產力 Google Calendar、Todoist、Trello、Asana、ClickUp 建行程、開任務、追進度
Marketing 行銷 HubSpot、Mailchimp、SendGrid、ActiveCampaign 加 lead、寄電子報、追客戶動態
AI（App 版） OpenAI、Anthropic、Google Gemini、Perplexity（放在 app-nodes/n8n-nodes-langchain.*） 單次呼叫 LLM 生成文案、摘要、翻譯；跟下一節 Cluster 版的 AI Agent 是不同節點
Developer 開發者 GitHub、GitLab、Jira、Bitbucket、Docker Hub 開 issue、建 PR、跑 CI 通知
Files & Cloud 檔案雲端 Google Drive、Dropbox、OneDrive、AWS S3 上傳附件、備份、跨雲搬檔
提示：你完全不需要記這張表。用不到就跳過，需要時再去抽屜搜尋。90% 的人常用的就那五六家（Slack、Gmail、Google Sheet、Notion、HubSpot、GitHub）。

App 節點的視覺特徵：左右兩邊都有圓點（左邊收上游的資料、右邊送下游），節點圖示通常就是那家 SaaS 的官方 logo（Slack 是紫色井字、Gmail 是紅色信封、Notion 是黑白翻頁）。看到 logo 你大概就知道這是哪家的節點了。

觀念：同一家 SaaS 通常會提供兩個節點——App 版（例：Slack，主動打 Slack API）跟 Trigger 版（例：Slack Trigger，被動聽 Slack Webhook）。名字很像但職責相反，別選錯。

Core 節點：內建流程／資料／通用工具

Core 節點是 n8n 自己內建的節點集合（官方檔案在 core-nodes/），數量比 App 節點少但每個都關鍵。它們職責是管 workflow 內部的資料流、控制流、以及不綁 SaaS 的通用工具——像水管的三通、閥門、開關，加上 HTTP Request 這種萬用鑰匙。

UI 抽屜裡的分類名稱在近期版本改過幾次：早期叫 Core Nodes，之後拆成 Flow / Data Transformation / Files / Helpers 這幾個小分類（實際字樣依你 n8n 版本會略有差異）。分不清就用搜尋。

觀念：很多 Trigger 節點（Schedule Trigger、Manual Trigger、Chat Trigger、Webhook、n8n Form Trigger、Execute Sub-workflow Trigger）在官方檔案樹上其實也放在 core-nodes/——因為它們是 n8n 內建、不綁 SaaS。這證明「Trigger」是功能角色，「Core」是檔案分類，同一個節點兩個標籤都貼得上。
Core 節點做什麼哪一章細講
IF 條件分支（true 走一條路、false 走另一條） 第 15 章
Switch 多分支（依欄位值走不同路） 第 15 章
Merge 把多路資料合成一路（append / combine / choose） ch16
Split In Batches 把一大批 item 分批處理，避免打爆 API rate limit ch16
Item Lists 陣列操作（去重、排序、聚合、拆開） ch16
Set / Edit Fields 加欄位、改欄位名、重排、扁平化 第 18 章
Code 寫幾行 JavaScript 或 Python 補現成節點不夠的洞（舊版叫 Function，已在 n8n 1.0 併入 Code；官方文件的 Function 頁面現在是 404） ch20
Wait 暫停一段時間（等 5 秒、等到明天 9:00、等 Webhook） ch17
Execute Workflow 呼叫另一條 workflow（sub-workflow） ch19
HTTP Request 打任何 REST API（沒有官方節點時的萬用鑰匙） 第 12 章
注意：HTTP Request 官方明確歸類在 Core nodes——因為它不綁特定 SaaS、是 n8n 內建的通用工具。功能上它會打外部 API，但這不代表它「同時是 App 節點」；App 節點的定義是「一家 SaaS 一個節點」，HTTP Request 是萬用打 API 的介面。你只要記得：找不到某家 SaaS 的專屬節點 → 用 HTTP Request 自己打就好。

Core 節點的視覺特徵：左右兩邊都有圓點（IF、Switch 因為要分支，右邊會有多個輸出圓點），節點圖示是抽象幾何——IF 是分岔箭頭、Merge 是箭頭合流、Set 是筆或欄位圖、Code 是尖括號 </>。看不到 SaaS logo 的節點，八成就是 Core。

Cluster 節點：AI Agent 那一整包群組節點

Cluster 節點是官方在 integrations/builtin/cluster-nodes/ 底下的第四大家族，也是 2024 之後 n8n 生態最大的架構變化。它不是「一顆節點」而是「一群節點的群組」——每個 cluster 都有一個 root node（主節點，例：AI Agent），再往下掛數個 sub-nodes（子節點）提供能力。

典型結構長這樣（AI Agent root 底下掛四種 sub-node）——

位置節點類型典型範例做什麼
Root（一個） AI Agent、Basic LLM Chain、QA Chain、Summarization Chain、Text Classifier、Information Extractor、Sentiment Analysis AI Agent Cluster 的主邏輯；正常資料流從左邊進、右邊出
Sub-node（多個） Chat Model OpenAI Chat Model、Anthropic Chat Model、Google Gemini Chat Model、Groq、Ollama 掛在 root 底部的 ai_languageModel 接點，提供推理引擎
Sub-node Memory Simple Memory、Postgres Chat Memory、Redis Chat Memory、Zep 掛 ai_memory 接點，讓 agent 記得上一輪對話
Sub-node Tool Calculator、Wikipedia、SerpAPI、Code Tool、HTTP Request Tool、任何 App 節點掛成 Tool 掛 ai_tool 接點，agent 決定何時呼叫哪個工具
Sub-node Vector Store / Retriever / Embeddings / Output Parser PGVector、Pinecone、Simple Vector Store、OpenAI Embeddings、Structured Output Parser 掛在對應的 ai_* 接點做 RAG、embedding、輸出結構化

Cluster 節點的視覺特徵超好認——root 節點底部會多出幾個橫向朝下的方形接點（不是 Trigger／App／Core 那種左右圓點），每個接點標著 Chat Model／Memory／Tool／Vector Store。你把對應的 sub-node 從下往上掛進去，n8n 才會判定這個 cluster 完整、能跑。

常見誤解：很多教學會說「AI 節點是獨立的 Advanced AI 分類」——這在官方文件裡不存在這個標籤。正確講法是：AI 生態被拆成兩層——App 版 AI（OpenAI、Anthropic、Gemini 這種放在 app-nodes/，單次呼叫）跟 Cluster 版 AI（AI Agent + 一票 ai_* sub-node，放在 cluster-nodes/）。UI 抽屜裡它們會擺在 AI 或 Advanced AI 標籤下方便瀏覽，但底層檔案分類就是這兩個。

第 21 章會拆 cluster 的完整 root+sub 組合方式跟 ai_* 接點細節，這章你只要記得：底部有多個朝下接點的節點 = Cluster root、被吸上去掛在那些接點下方的 = sub-node。

怎麼看一個節點是哪一家族

認完四大家族，實戰時最有用的技巧是看一眼就能分類。用這四個特徵對照，一秒判斷——

  1. 看下方有沒有 ai_* 接點 → Cluster root

    節點底部有幾個橫向朝下的方形接點、標著 Chat Model／Memory／Tool／Vector Store——這就是 Cluster root 節點（AI Agent、Basic LLM Chain、QA Chain 等）。反過來，如果一個節點只有頂部一個朝上的接點準備被 root 吸走，那它就是 sub-node（Chat Model、Memory、Tool 等）。

  2. 看左邊有沒有輸入圓點 → Trigger

    左邊沒有圓點（只有右邊出線）→ 一定是 Trigger。你在 Canvas 上看到一個節點孤零零掛在最左邊、前面沒接東西，就是 Trigger。名字通常有 "Trigger" 或 "On..." 字樣（Slack Trigger、Schedule Trigger、Webhook、On form submission）。

  3. 看圖示是 SaaS logo 還是抽象幾何 → App 或 Core

    左右兩邊都有圓點、圖示是某家 SaaS 的 logo（Slack 紫井字、Gmail 紅信封、Notion 黑白頁）→ 幾乎一定是 App 節點。圖示是抽象幾何（分岔、合流、齒輪、尖括號）→ 幾乎一定是 Core 節點。

  4. 看抽屜分類

    n8n 抽屜本來就分好類了：Triggers、Actions in apps（App 節點依 SaaS 分類）、Core（含 Flow / Data Transformation / Files / Helpers 等子區）、AI 或 Advanced AI（Cluster 節點）。分不清就回抽屜看它被放在哪個標籤下。

一個 workflow 通常的節奏

四大家族在真實 workflow 裡怎麼組合？從最短到最複雜，大概四種節奏：

  1. 最短：Trigger → 1 個 App

    「每天早上 8:00 傳一則固定訊息到 Slack」——Schedule Trigger 接 Slack (Send Message)，完。兩個節點、一條線，這是最簡單的 workflow 形狀。適合當提醒、當 reminder 用。

  2. 常見：Trigger → 讀資料 App → Core 過濾 → 寫資料 App → 通知 App

    「每天早上抓客服 ticket、只留 urgent 的、寫進 Notion、通知業務主管」——Schedule Trigger → HTTP Request（讀 ticket API） → IF（priority == urgent） → Notion（新增頁） → Slack（通知）。這是最典型的 5 節點 workflow，公司 8 成的自動化都長這樣。

  3. AI：Chat Trigger → AI Agent（Cluster）→ 回覆

    「客戶在網頁 chat 打字 → AI 客服回答」——Chat Trigger → AI Agent，AI Agent 底下掛 OpenAI Chat Model（推理）＋Simple Memory（記對話）＋Wikipedia Tool（查資料）＋HTTP Request Tool（呼叫內部 API）。畫面上看起來像一顆節點底下長出四根鬚，這是最典型的 cluster 形狀。

  4. 複雜：多 Trigger → IF 分支 → 平行 App → Merge → Sub-workflow → 錯誤處理

    「新客戶進來（Webhook + Manual + Schedule 三個 Trigger）→ 依國家分流 → 並行寄歡迎信 / 加 CRM / 開 Slack 頻道 → 合流回主線 → 呼叫『發通知』sub-workflow → 錯了自動 retry 3 次還不行就通知 IT」。這種 15+ 節點的複雜 workflow 你到後面幾章才會慢慢碰到，不用怕。

看得出來，Trigger 通常 1 個（有時多個）、App 是主力（占節點數 60% 以上）、Core 節點是把 App 串起來的水管接頭（IF 決定往哪走、Set 整型資料、Merge 合流）、Cluster 是 AI 專用的「一顆帶好幾根鬚」結構。

提示：你以後看到別人分享的 workflow 截圖，可以用這四種節奏對號入座：只有兩三塊就是「最短」、五到八塊是「常見」、看到某顆節點底下伸出多根鬚就是「AI cluster」、十幾塊帶分岔就是「複雜」。看得懂結構才看得懂 workflow 在幹嘛。

抽屜怎麼找節點最快

知道分類是為了看得懂，但實戰時找節點你根本不會一個個滑分類。直接打關鍵字比什麼都快。

  1. 打服務名字：Slack、Sheet、Gmail、Notion

    抽屜最上面有搜尋框，輸入 slack 就會濾出 Slack 相關的節點（Slack、Slack Trigger 都會出現）。99% 的常用整合這樣就找得到。

  2. 打功能字眼：if、set、code、wait、http

    Core 節點沒有 SaaS 名字，用功能字搜。輸入 if 會出現 IF、Switch；輸入 set 會出現 Set / Edit Fields；輸入 http 出現 HTTP Request。

  3. 找不到 → 可能是社群節點（community package）

    比較小眾的服務（例如某台灣本土 SaaS）可能官方沒做節點，但 n8n 有 community nodes（社群套件）機制——需要管理員在後台裝。這個屬於進階操作，找 IT 部門幫忙裝就好。

  4. 完全沒有這家 SaaS 的節點 → 用 HTTP Request 自己打

    官方跟社群都沒有？沒問題，只要那家 SaaS 有 REST API，用 HTTP Request 節點（第 12 章）照 API 文件填 URL、method、header、body 就能打。這是 n8n 的萬用鑰匙——只要對方有 API，你就打得到。

常見狀況排除

剛開始接觸節點抽屜，最常遇到這幾個狀況：

  1. 節點抽屜打不開

    兩種方式：Canvas 空白處按 +、或是新 workflow 就按右邊面板的 Add first step。已經有節點的話，把游標移到某個節點右邊的圓點上會出現 +，點下去也會開抽屜（自動接在該節點後面）。

  2. 抽屜太多分類找不到

    不要一頁一頁滑，直接在最上面的搜尋框打關鍵字。分類是為了瀏覽的人設計的，實戰用搜尋最快。

  3. 我要的節點打了搜不到

    三種可能：（1）拼字對不上——例如你打 google sheets 找不到，試 sheets；（2）可能是社群節點，需要管理員在後台裝 community package；（3）該服務沒官方節點——那就改用 HTTP Request（第 12 章）對它 API 打。

  4. 節點名字改了找不到（Function → Code、Set → Edit Fields）

    n8n 定期會改節點名字。最常見的兩個：Function 節點在 v1 已經完全被 Code 取代，官方文件的 Function 頁面現在是 404，舊 workflow 匯入時會自動遷移或標為 legacy；Set 也改叫 Edit Fields (Set)。舊教學裡的名字搜不到就打新名字（Code、Edit Fields）。

  5. 選了 SaaS App 節點但左邊沒有輸入圓點

    你可能選成 SaaS 的 Trigger 版了（例如 Slack Trigger 而不是 Slack）。刪掉重選純 App 版本——搜尋 slack 時同時會出現兩個節點，選沒有 "Trigger" 字樣那個。

  6. 拉了 Core 節點但不知道要接哪

    Core 節點通常放在 workflow 中間（Trigger 跟最終 App 節點之間）。IF 放在你要分岔的位置、Set 放在你要整型資料的地方、Merge 放在多路合流處。單獨拉一個 Core 節點沒用，它必須夾在別的節點中間才有意義。

  7. 拉了 AI Agent 但按 Execute 就報錯「no language model」

    AI Agent 是 Cluster root 節點，它必須從底部的 Chat Model 接點掛一個 sub-node（OpenAI Chat Model 或 Anthropic Chat Model 等）才能跑。同理，如果啟用了 Memory／Tool 但沒掛對應 sub-node，也會報接點空的錯。單獨一顆 AI Agent 不會動。

常見問題

n8n 的節點總共有幾種？

n8n 官方支援 400+ 個節點（n8n.io/integrations 的清單）；加上社群套件（community nodes）還有幾百個。實務上 8 成的自動化用不到 20 個節點，別被數字嚇到。

最常用的到底哪幾個？

Woow 內部觀察下來，這 8 個節點涵蓋 80% 的 workflow：

  • Schedule Trigger（Trigger／Core）——定時跑
  • Webhook（Trigger／Core）——外部打進來
  • Slack（App）——通知
  • Gmail（App）——寄信
  • Google Sheets（App）——記錄
  • HTTP Request（Core）——打任何 REST API
  • IF（Core）——條件分支
  • Edit Fields (Set)（Core）——整型資料

把這 8 個玩熟就可以在公司獨當一面了。

AI Agent 節點算哪一類？

算第四大家族——Cluster nodes。官方文件明確放在 integrations/builtin/cluster-nodes/root-nodes/n8n-nodes-langchain.agent。AI Agent 是 root，底下必須掛 sub-node（Chat Model、Memory、Tool、Vector Store）才會動。UI 抽屜通常在 AI／Advanced AI 標籤下方便瀏覽，但底層檔案分類就是 cluster。第 21 章會拆完整組合方式。

順帶澄清：OpenAI、Anthropic、Google Gemini 這幾個「單次呼叫 LLM」的節點不是 cluster，它們是 App 節點（放在 app-nodes/n8n-nodes-langchain.*），跟 AI Agent 不同層。

新版節點會不會取代舊的？

n8n 有時候會發新版節點（例：Google Sheets 有 v1、v2；Set 節點在 v1 之後改叫 Edit Fields）。舊版一般會保留讓現有 workflow 不會壞掉；新拉的建議用新版（功能更完整、bug fix 較新）。抽屜裡搜 sheets 會同時出現舊版跟新版，選最新的那個。

Trigger 節點跟 App 節點差在哪？

Trigger 是被動聽（時間到了、Webhook 進來、SaaS 有事件發生），會自動啟動 workflow；App 節點是主動做（傳訊息、寫表格、開帳號），需要上游先送資料才會執行。視覺上 Trigger 左邊沒圓點、App 兩邊都有圓點。同一家 SaaS 通常提供兩個：Slack Trigger 聽 Slack 事件、Slack 主動打 Slack。

Core 節點會不會跟 SaaS 講話？

大部分不會——IF、Set、Merge、Wait、Code 這些純粹在 workflow 內部處理資料流跟控制流。少數 Core 節點會打外部：HTTP Request（打任何 REST API）、SSE Trigger／Webhook（聽外部進來）、Email (Send)／FTP（通用協定）。這些不算「App 節點」，因為 App 節點的定義是「一家 SaaS 一個節點」；這些是「通用網路工具」，所以歸 Core。

Function 節點還在嗎？

不在了。Function 節點在 n8n v1（2023-07）已經被 Code 節點完全取代——功能一樣但支援 Python，官方文件 core-nodes/n8n-nodes-base.function/ 頁面現在是 404。舊 workflow 匯入 v1+ 時會被自動遷移或標為 legacy。新拉一律用 Code。

官方文件在哪查節點細節？

兩個地方：（1）整合節點看 n8n.io/integrations，每家 SaaS 有獨立頁面列所有 operation 跟參數；（2）Core 節點看 docs.n8n.io/integrations/builtin/core-nodes/，官方文件講每個 Core 節點的細節跟範例。

下一步做什麼？

去第 8 章從零拉第一條 workflow：Schedule Trigger（每天 8:00）→ Google Calendar（抓今日行事曆）→ Slack（傳訊息）。剛好就是 Trigger + 2 個 App 的最短節奏，把這章講的四大家族先感受前三個；第 21 章再進 Cluster。
